# 不依赖 MTAIC 的人工执行工作流

这套工具让模型规则决定买卖内容，由人核对并操作券商软件。当前交付的是可运行的纸面工作单与成交核账工具，不连接华泰、不下单、不撤单，也没有批准实盘。正式冻结策略未改变。

## 当前结果

本轮检查的前向状态是 2026-09-11 市场日：保存信号 0，模拟成交 0，非月末信号日。基于没有提供合格信号的输入，已生成[当前工作单](../research/manual_execution/status-2026-09-13-v1.md)，没有任何买卖条目。它不是实时市场扫描，也不能证明之后没有新信号。

此前人工工作单依赖事后的模拟开盘成交。新增版本使用已有 `admit_signal` 的信号时序/结构校验，加上当前账户及报价快照重新计算份数和限价，不将历史成交价当作今天可交易的价格。上游仍须通过已有 `reviewed_signal.build_event` 审核价格、公司行动和交易日历；这里的审核标签与哈希本身不是外部真实性证明。

## 工作分工

| 环节 | 系统处理 | 人工处理 |
|---|---|---|
| 信号 | 读取预先保存、处于有效执行窗口内的目标权重 | 不凭感觉修改为另外一只基金 |
| 清单 | 按报价、可用现金、费用假设与可卖份额计算限价和数量 | 核对证券、方向、份数、价格与有效期 |
| 执行 | 不操作券商 | 在获准实盘前仅演练；获准后由账户本人确认委托 |
| 未成交 | 不猜测成交、不自动补单 | 查询最终委托状态；需要撤单时确认撤单成功 |
| 核账 | 导入脱敏成交 CSV，计算现金与持仓变动、费用、滑点和时延 | 核对券商账单；佣金和其他费用未确定时不能视为最终账本 |

不需要提供账号密码、客户号或 API 密钥。实际账户的可用现金、各证券持仓和可卖份额、未完成委托、具体费率与报价是必要输入；纸面余额不能冒充券商余额。

## 已实现的边界检查

工作单仅在信号执行窗口内生成；账户快照不得早于当前时钟 60 秒，报价必须不足 60 秒且不在未来。有效期取信号截止与报价到期的较早者。60 秒是本版工程参数，尚未证明适合人的实际操作速度；过期要重新核对，不能直接放宽窗口追价。

买入限价使用输入卖一，卖出限价使用输入买一，并检查价格与输入最小变动单位一致。报价由外部提供，并非系统已接入认证实时行情；限价也不保证成交或市场深度足够。目标数量向下按 100 份折算，卖出检查实际可卖份额，不假设当天买入就可卖。

有未完成委托、资金不足以支付买入与预计佣金、可卖份额不足时，不输出可用买卖条目。尚未成交的卖单不能为买单融资。本版会阻断整个批次，而不静默缩小策略；需明确处理资金或重新制定批次，不能擅自补单。

成交核对要求唯一成交编号、绑定工作单、按成交时间排序，检测错方向、超量、超限价、非有限值、未来成交和重复记录。部分撮合可以不是整手；委托整手约束不能错误套到每一笔撮合上。过期成交会记入报告但标记账本无效，需要核实撤单状态。

输入成交只是导入报告，不是自动取得的券商认证。核对异常时的现金持仓是部分重建值，不可直接作为下一张清单的输入。完整成交也不代表产生利润：没有加入后续估值、分红和未实现收益。

## 本地使用

在 `F:\AOAE` 运行。每次输出使用新文件名，避免覆盖证据。

```powershell
.venv/python.exe scripts/manual_ticket.py prepare --input research/manual_execution/no-signal-request.json --output research/manual_execution/new-status.json
```

输出同名 JSON 和中文 Markdown 工作单。完整输入结构见[工程样例](../research/manual_execution/engineering-example.json)。样例的日期、审核摘要、证券报价和余额全部为合成测试资料，不是建议买入，也不是经过核实的未来开市安排。

以下指定时钟只用于重放工程样例，不得将其输出当作当前交易指令：

```powershell
.venv/python.exe scripts/manual_ticket.py prepare --input research/manual_execution/engineering-example.json --now 2026-10-08T09:31:05+08:00 --output research/manual_execution/new-demo-ticket.json
```

实际成交导出需要先映射成[标准 CSV 表头](../research/manual_execution/fills-template.csv)。每行对应一笔唯一撮合；`commission_cny` 填该行分摊的佣金，`other_fees_cny` 填其他费用，不重复累计同一委托总费用。未知费用不能填零冒充已确认；费用未最终入账时等待核实。证券代码作为文本保留，时间含 `+08:00` 时区。

```powershell
.venv/python.exe scripts/manual_ticket.py reconcile --input research/manual_execution/engineering-ticket-v1.json --fills research/manual_execution/engineering-fills.csv --now 2026-10-08T09:31:20+08:00 --output research/manual_execution/new-demo-reconciliation.json
```

演练样例：虚拟现金 10,000 元，模拟买入 1,200 份，单价 4 元，费用 14.40 元，核算剩余现金 5,185.60 元。这个数是现金核算，不是盈利。已有[完整演练核账输出](../research/manual_execution/engineering-reconciliation-v1.json)。

## 尚未完成的实盘条件

现已增加只读前向账本入口：`scripts/prepare_current_manual_ticket.py --output <新文件名.json>`。它校验事件链、冻结记录及待执行信号的审核源文件；有待执行信号时，通过 `--snapshot` 提供新账户/报价快照，不得使用纸面账户的30万元余额替代。无待执行信号时输出空清单。有信号但缺快照、已过期或审核源改变时阻断，不回填。

工具仍未接入实时盘口或适配所有券商原生表格，也没有为这个新入口创建定时任务。它复用已保存的信号，不负责新增或认证信号数据。

人工执行比历史开盘假设更晚。本版记录相对模型开盘窗口的实际延迟和相对工作单报价的滑点，`delay_backtest_validated` 固定为否。尚未取得分钟级或逐笔执行资料，不能声称已完成历史延迟回测。缺少这些证据时，旧开盘回测收益不能原样迁移给人工执行方案。

接下来有合格预存信号和独立核实的账户/报价输入，才可生成新的纸面工作单。真实资金还需要账户费率与权限核实、执行证据和单独明确授权；拿不到 MTAIC 本身不再是这个工作流的技术阻碍。

本轮完整回归通过 300 项测试，其中新增人工工作单测试 13 项；JSON 清单、中文工作单和 CSV 导入演练均已运行。现金余额另用直接十进制算式核对，而不是仅检查状态字符串。

第一性原理检查：本次没有新增经济付款方或收益信号，只减少手工执行与核账出错的机会。净可执行增量仍未知，必须与原策略及简单基线在同一人工执行口径比较。资金毁灭概率未估计；限价和到期提醒不保证止损成交。软件测试通过不等于可以承诺收益。
